# Итоговый проект: валютный кошелёк

Автор: Фёдор Симонов. Группа: М26-555.
Название проекта: `finalproject_simonov_m26_555`.

Консольное приложение для регистрации пользователей, управления виртуальными
портфелями фиатных и криптовалют, симуляции покупки/продажи и просмотра курсов.
Проект оформлен как устанавливаемый Python-пакет и использует ООП.
Выполнены разделы 1 «Подготовка», 2 «Модели и CLI» и 3 «Усложнение
и гибкость модели данных»: иерархия валют, доменные исключения,
Singleton-конфигурация и доступ к данным, журналирование операций.

## Подготовка и запуск

Требуются Python 3.12 и uv версии 0.5 или выше. Make необязателен.
Версия Python закреплена в `.python-version`.
Выполняйте команды из директории `python/final_project`:

```sh
uv sync --locked
uv run --locked wallet
```

uv создаст виртуальное окружение `.venv` и установит зависимости
из `uv.lock`, включая сам пакет и инструменты разработки.
Альтернативные способы запуска того же интерфейса:

```sh
uv run --locked python main.py
uv run --locked python -m finalproject_simonov_m26_555
```

Программа работает как интерактивная сессия: вводите команды после `>`.
`help` показывает список команд; `<команда> --help` — её аргументы.
`exit`, Ctrl+C и конец ввода завершают программу без traceback.

## Команды

| Команда | Аргументы | Назначение |
| --- | --- | --- |
| `register` | `--username <имя> --password <пароль>` | Создать пользователя и пустой портфель |
| `login` | `--username <имя> --password <пароль>` | Войти в систему |
| `show-portfolio` | `[--base USD]` | Показать кошельки; база по умолчанию берётся из конфигурации |
| `buy` | `--currency BTC --amount 0.05` | Добавить указанное количество валюты |
| `sell` | `--currency BTC --amount 0.01` | Продать указанное количество валюты |
| `get-rate` | `--from USD --to BTC` | Показать прямой и обратный курс, время обновления |
| `help` | — | Показать справку |
| `exit` | — | Завершить сессию |

Пример команд внутри запущенной программы:

```text
register --username alice --password 1234
login --username alice --password 1234
show-portfolio
buy --currency BTC --amount 0.05
sell --currency BTC --amount 0.01
buy --currency EUR --amount 200
show-portfolio --base EUR
get-rate --from USD --to BTC
exit
```

Регистрация не выполняет вход автоматически. Просмотр портфеля, покупка и продажа
доступны после `login`; получение курса доступно без входа. Сессия хранится
в памяти: после перезапуска нужно войти снова. Неудачный вход сохраняет
ранее открытую сессию.

Имя пользователя не может быть пустым и уникально с учётом регистра.
Внешние пробелы имени удаляются; имена и пароли с пробелами заключаются
в кавычки, например `--username "Alice Smith" --password "my secret"`.
Пароль содержит не менее четырёх символов; сохраняется SHA-256 от UTF-8
`password + salt`, соль генерируется отдельно для каждого пользователя.
Ответы команд не содержат паролей, хешей и соли.

Коды валют приводятся к верхнему регистру: 2–5 латинских букв или цифр,
первый символ — буква, пробелы внутри не допускаются.
`amount` — количество самой валюты, положительное конечное число.
Ноль, отрицательные значения, `nan` и `inf` отклоняются. Балансы хранятся
как `float`, округление выполняется только при выводе.

## Типы валют и ошибки команд

Абстрактный `Currency` задаёт публичные свойства `name`, `code`
и метод `get_display_info()`. Проверки работают и при последующем присваивании
свойствам. `FiatCurrency` добавляет страну/зону эмиссии, `CryptoCurrency` —
алгоритм и конечную неотрицательную капитализацию.

Фабрика `get_currency(code)` нормализует ввод и возвращает новый экземпляр
из реестра USD, EUR, RUB, BTC, ETH. Данные одного экземпляра можно менять
без изменения следующих результатов фабрики. `help` использует полиморфный
`get_display_info()` и показывает, например:

```text
[FIAT] USD — US Dollar (Issuing: United States)
[CRYPTO] BTC — Bitcoin (Algo: SHA-256, MCAP: 1.12e12)
```

Алгоритмы и капитализация в реестре — демонстрационные метаданные,
они не обновляются из API.

Доменные исключения наследуются от `DomainError(ValueError)`.
Ошибки перехватываются в CLI; после сообщения можно продолжать ввод.

| Команды | Ошибка | Сообщение и действие CLI |
| --- | --- | --- |
| `sell` | `InsufficientFundsError` | `Недостаточно средств: доступно 0.0400 BTC, требуется 0.0500 BTC` |
| `buy`, `sell`, `get-rate`, `show-portfolio` | `CurrencyNotFoundError` | `Неизвестная валюта 'ABC'`; список кодов и предложение `get-rate --help` |
| `buy`, `sell`, `get-rate`, `show-portfolio` | `ApiRequestError` | `Ошибка при обращении к внешнему API: Курс BTC→USD недоступен`; предложение повторить позже или проверить сеть |
| `show-portfolio`, `buy`, `sell` | Не выполнен вход | `Сначала выполните login` |
| `buy`, `sell` | Некорректная сумма | `'amount' должен быть положительным числом` |
| Команды с чтением/записью данных | `StorageError` | Сообщение об ошибке JSON/файла; исходные повреждённые файлы сохраняются |

Отсутствующий при продаже кошелёк означает доступный баланс 0 и также
вызывает `InsufficientFundsError`. Ошибки локального хранилища не выдаются
за ошибку внешнего API. Неверные аргументы и незакрытые кавычки дают
сообщение без раскрытия введённого пароля.

## Модель торговли и курсы

Выбрана модель **симуляции балансов**, разрешённая уточнением преподавателя
от 13.10.2026. `buy` увеличивает баланс покупаемой валюты, `sell` уменьшает
баланс продаваемой. Отдельный USD-кошелёк при этих операциях не изменяется:
USD используется для оценки стоимости сделки. Начального капитала
и команды пополнения нет. USD можно купить и продать как обычную валюту.

При первой покупке кошелёк создаётся автоматически. Продажа требует
существующего кошелька и достаточного баланса. Неудачная операция не меняет
сохранённый портфель. `show-portfolio` использует PrettyTable и показывает
стоимость каждого кошелька и итог в выбранной базовой валюте.

Реальный Parser Service пока не подключён. Локальная заглушка возвращает
фиксированные, **не рыночные** курсы:

| Валюта | USD за одну единицу |
| --- | ---: |
| USD | 1.0 |
| EUR | 1.0786 |
| BTC | 59337.21 |
| RUB | 0.01016 |
| ETH | 3720.0 |

`RateService.get_rate(from_currency, to_currency)` возвращает `RateQuote`
с полями `rate` и `updated_at`. Сервис использует прямую пару, обратную
или кросс-курс через USD. Для одной и той же известной валюты курс равен 1.
Поддерживаемые коды определяются реестром: пара из локального кеша
не регистрирует новую валюту.

Кеш действителен меньше `RATES_TTL_SECONDS` (по умолчанию 300 секунд).
Если нужного свежего курса нет,
сервис вызывает провайдер-заглушку и сохраняет полученные значения с
`source: "Stub"` и временем UTC. Возраст кросс-курса определяется по более
старой из двух меток времени. При ошибке обновления устаревший курс
не используется; команда сообщает об ошибке. Провайдер и часы можно
подменить при тестировании и последующем подключении Parser Service.

## Конфигурация и Singleton

`config.json` необязателен и читается из текущей рабочей директории.
Без него используются встроенные значения. В исходном репозитории
можно создать локальную конфигурацию из примера:

```sh
cp config.example.json config.json
```

| Ключ | Значение по умолчанию |
| --- | --- |
| `DATA_DIR` | `"data"` |
| `RATES_TTL_SECONDS` | `300` |
| `DEFAULT_BASE_CURRENCY` | `"USD"` |
| `LOG_DIR` | `"logs"` |
| `LOG_FILE` | `"actions.log"` |
| `LOG_FORMAT` | `"json"` |
| `LOG_LEVEL` | `"INFO"` |
| `LOG_MAX_BYTES` | `1048576` |
| `LOG_BACKUP_COUNT` | `3` |

`DATA_DIR` содержит `users.json`, `portfolios.json`, `rates.json`.
Относительные пути разрешаются от директории запуска. `LOG_FILE` — имя
файла внутри `LOG_DIR`, без собственного пути. TTL — положительное конечное
число в диапазоне `timedelta`, размер ротации — положительное целое,
число резервных файлов — целое от 0. База должна существовать в реестре.
Допустимые уровни: DEBUG, INFO, WARNING, ERROR, CRITICAL; формат — только JSON.
Повреждённая или неверная конфигурация завершает запуск с понятной ошибкой.

`SettingsLoader` реализован через `__new__`: один экземпляр и одна загрузка
под блокировкой. `get(key, default=None)` возвращает значение или переданный
default, не позволяя менять кеш через вложенный объект. Повторный вызов
конструктора не перечитывает файл; другой явно указанный путь отклоняется.
Изменения конфигурации вступают в силу после перезапуска.

`DatabaseManager` также использует `__new__`, содержит один `JsonStorage`
и предоставляет его методы чтения/сохранения. `WalletService()` получает
оба синглтона; для тестов можно явно передать отдельное хранилище, настройки,
часы и сервис курсов. Импорт модулей сам по себе не создаёт экземпляров,
каталогов, JSON-файлов или обработчиков логов.

## Журнал операций

При запуске CLI настраивается выделенный logger `valutatrade_hub.actions`.
`@log_action("BUY", verbose=True)` и `@log_action("SELL", verbose=True)`
записывают операции в `logs/actions.log`. Регистрация и вход в этом разделе
не журналируются. Каждая запись — одна строка JSON в UTF-8, уровень INFO:

```json
{"timestamp":"2026-11-08T12:00:00+00:00","level":"INFO","action":"BUY","username":"alice","user_id":1,"currency_code":"BTC","amount":0.05,"rate":59337.21,"base":"USD","result":"OK","error_type":null,"error_message":null,"before":0.0,"after":0.05}
```

Успех фиксируется после сохранения портфеля. При исключении записываются
`result: "ERROR"`, его тип и сообщение, затем то же исключение пробрасывается
в CLI. Недоступные значения — `null`; нечисловые, бесконечные и NaN-суммы
не попадают в JSON как некорректные числовые константы.

`verbose=True` добавляет балансы `before`/`after` успешной операции.
При `verbose=False` этих полей нет. Пароли, хеши, соли, объекты пользователей
и полные аргументы вызовов не сериализуются. Декоратор сохраняет имя,
документацию и сигнатуру метода через `functools.wraps`.

По умолчанию файл ротируется при достижении 1 МиБ, сохраняются до трёх копий
`actions.log.1`–`actions.log.3`. Повторная настройка не дублирует обработчики
и записи; журнал не выводится в консоль. Уровень DEBUG можно включить
через конфигурацию. Сбой записи журнала не отменяет уже сохранённую сделку.

## Хранение данных

При первом запуске создаётся каталог `DATA_DIR` (по умолчанию `data/`)
**относительно текущей рабочей директории**:

- `users.json` — список пользователей, включая хеш пароля, соль и дату регистрации.
- `portfolios.json` — портфели с `user_id` и словарём кошельков.
- `rates.json` — пары вида `EUR_USD`, значения `rate`, `updated_at`, источник и время обновления.

Отсутствующие файлы создаются автоматически: пользователи и портфели —
пустые списки, курсы — пустой объект. Данные перечитываются перед использованием.
Повреждённые JSON-файлы, повторяющиеся пользователи, неверные балансы
и другие ошибки структуры вызывают понятное сообщение; исходные файлы
не перезаписываются. При ошибке данных на старте программа завершается
с кодом 1; ошибка во время сессии позволяет продолжить ввод команд.

Каждый файл сохраняется через временный файл и атомарную замену.
При ошибке сохранения портфеля во время регистрации запись пользователя
откатывается. Контекст `operation()` удерживает reentrant lock на весь
сценарий чтение→изменение→запись через общий экземпляр хранилища;
вложенные вызовы не блокируют сами себя. Хранилище рассчитано на один процесс:
межпроцессных блокировок и общей crash-safe транзакции между JSON-файлами нет.
Форматы данных из раздела 2 сохранены, миграция не требуется.
Стандартные runtime JSON-файлы, локальный `config.json`, журналы,
окружение и артефакты сборки исключены из Git.

## Структура проекта

```text
data/                              # runtime JSON-файлы
valutatrade_hub/
    decorators.py                  # @log_action
    logging_config.py              # JSON Lines и ротация
    core/
        currencies.py              # Currency, FiatCurrency, CryptoCurrency, фабрика
        exceptions.py              # доменные исключения
        models.py                  # User, Wallet, Portfolio
        utils.py                   # валидация, время, курсы заглушки
        storage.py                 # JsonStorage
        rates.py                   # RateService, RateQuote
        usecases.py                # WalletService и текущая сессия
    cli/
        interface.py               # разбор команд и вывод
    infra/
        settings.py                # Singleton SettingsLoader
        database.py                # Singleton DatabaseManager
src/finalproject_simonov_m26_555/    # совместимая точка входа из раздела 1
tests/                             # unittest, временные файлы, без сети
config.example.json                # пример локальной конфигурации
main.py                            # запуск из корня
```

Модели не обращаются к файлам и не печатают сообщения. CLI разбирает команды
через `shlex` и `argparse`, вызывает бизнес-логику из `core/usecases.py`
и форматирует результаты. Название дистрибутива сохранено;
основной импортируемый пакет — `valutatrade_hub`.

## Зависимости и проверки

- `prettytable` — единственная внешняя зависимость приложения.
- `ruff` — анализ и форматирование, только для разработки.
- `unittest`, `json`, `hashlib`, `secrets`, `shlex` и другие используемые
  модули входят в стандартную библиотеку Python.

```sh
make check
# Без Make:
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m unittest discover -s tests -t . -v
```

Настройки Ruff: Python 3.12, длина строки 88 символов, проверки
стиля (`E`), ошибок (`F`) и порядка импортов (`I`).

Тесты проверяют модели, сохранение и восстановление состояния, сессии,
торговлю, изоляцию пользователей, ошибки данных и записи, свежесть курсов,
прямые/обратные/кросс-пары, иерархию валют, типы ошибок, одиночность
и инициализацию синглтонов, настройку TTL/базы/путей, согласованные операции,
структуру и ротацию логов, отсутствие секретов и полную CLI-сессию.
Используются временные каталоги, подменяемые часы и провайдер;
сетевых запросов нет.

Также доступны `make install`, `make run`, `make test`, `make format`
и `make build`. Команда `make format` изменяет форматирование исходников.

## Разработка

Используется GitHub Flow: отдельная ветка для следующей задачи,
проверки перед коммитом и осмысленный коммит после завершения этапа.
Файл `uv.lock` хранится в Git. Реальные API, расписание обновлений,
отдельная история транзакций и кеширование через замыкания
остаются за пределами реализованных разделов 1–3.
